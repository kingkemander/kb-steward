# kb-steward 知识库管家 v1.3.1

目标：把散在个人电脑里的文件，变成全公司能用的文件管理系统——**一套编号、一本总目录、三层晋升、权限域视图**。不是"把文件夹搬整齐"，是"给每份公司文件登记户口"。

## 大白话总览（人先读这段）

把公司想成一个档案室，每个员工的电脑是自己家。

1. **先别搬东西，先列清单**：每人的 AI 把电脑过一遍，列出哪些对公司有用、哪些是个人物品。个人的不出家门。
2. **老板定抽屉**：档案室按"什么东西"分抽屉——资质、业绩、人员、制度、模板，不按部门分（部门会改组，这些东西不会）。每个抽屉给个编号，像快递柜号，编号永不变，新老员工都找得到。
3. **给东西上户口**：放哪个抽屉、谁负责、谁能看、什么时候过期，全写进一本总账。部门不另建档案室，只是"负责几个抽屉+拿这几把钥匙"——这就是融合到组织，不是把三堆文件夹合并。
4. **都确认了才搬**：员工核、经理核、老板签字，然后一次把东西放进抽屉。先复制不删原件，错了能撤。
5. **以后查账不翻箱**：同一份东西只存一次，谁有权限谁看见。新东西先放"待分拣"篮子，用到再上户口。

AI 定抽屉靠**打开读内容**，不看文件名；拿不准就问人，不许猜。

## 0. 角色、身份与部门记忆

**首次运行：记住「我是谁」——姓名、部门、职位。** 这三样决定个人索引包的 `owner` 字段、人员架构表的路由、能不能开目录。

- 先查有没有已存的身份信息（之前提供过 / 平台记忆里）→ 有就直接用，**不再问**。
- 用户**主动提供了**身份 / 部门信息 → 记下来（存本地 profile 或平台记忆），**不再问**。
- 用户**没提供** → 启动时主动询问三件事：
  1. **姓名** → 写进个人索引包 `owner.name`
  2. **部门** → 人员架构表 `members` 归属，决定个人包发给哪个 manager
  3. **职位** → 判断是员工（只能上报）还是管理者（可融合 + 开目录）

- 启动读账号权限标签：系统管理员 → G；管理员 → M；员工 → E。读不到问一次。一人多标签按流程顺序执行各模式。
- 模式：E-目录检索 / E-校对与改名/上传 / M-校对 / G-终整理 / CMD-命令执行 / REVIEW-审看签核。
- 收到「命令」进 CMD；M/G 收到「结果索引」进 REVIEW；其余按标签。

## 1. 理解：搭文件系统的四条原则

1. **按业务职能分类，不按部门、不按文件类型**（ISO 15489 业务分类方案：职能→活动→事务）。部门会改组，职能不变。「资质/业绩/人员/制度」是职能，「销售部文件夹」不是。部门不拥有独立的树，部门 = 若干类目的 owner + 一个权限域。
2. **一套编号管到底**（Johnny.Decimal）：区 ≤10、每区类目 ≤10、深度 ≤3，文件只放在 ID 文件夹里；中央索引（00.00）= 总目录；编号永不复用；归档镜像原结构；先审计后设计、留空槽。
3. **文件夹给人导航，元数据给机器检索**（Firefly 虚拟目录 / ISO 元数据原则）：同一份文件物理只存一次；部门视图、公司视图靠「JD 编号 + 权限域」标签生成。**融合 ≠ 复制三套文件夹树**，没有元数据的共享盘只是堆文件，不是记录系统。
4. **个人空间与公司空间是两套系统**（PARA）：电脑上是工作区，公司里是文件计划；两者之间的桥是「晋升登记」，不是整体搬迁。

安全底线（开源整理 Agent 的共识）：先预览后执行、白名单根目录、复制不移动、高风险标记、全程可回滚。

## 3. 个人空间约定（E 模式；PARA 轻量版）

```
00 收件箱(待分拣) 10 项目(有截止) 20 领域(持续职责) 30 资源(参考模板) 40 归档(已完成) 90 个人(永不晋升)
```

- 新文件先入收件箱；边用边理，不一次整理全部（渐进式）。
- **晋升三条件**（个人→公司记录）：对公司有用 + 版本定稿 + 归属可确认。满足才登记：JD 编号 + 元数据 + owner + 域。公司版为权威版，个人留副本标「工作副本」。
- 90 个人目录永不扫描上传；扫描默认排除。

## 4. E-目录检索

### 4.0 前置分拣门（不花钱，先于一切 AI）

**原则：越往下越贵，能在上层解决绝不下沉；能直接判的直接判，模糊的才加层。** 废弃「命中即停」硬规则，改分层漏斗 + 多信号加权打分。

**L1 硬规则（秒判，一票否决，不进打分）**
- 垃圾：`.~`/`~$`/`.DS_Store`/Thumbs.db；0 字节；测试件（t/fonttest/内容=测试中文）。
- 开发不晋升：代码扩展名（.py/.js/.java/.go/.sh 等）、node_modules/dist/.git/`__pycache__`、agent 配置（SKILL/CLAUDE/DEV-PLAN）。代码类扩展名可靠，直接判，不打分。

**⚠️ 顺序铁律：路径排除必须跑在格式白名单之前。**
实测踩坑：30 份 `umath-validation-set-*.csv`、`philox/mt19937/pcg64-testset-*.csv` 加 1 份 `default.docx` 全在 `envcad-validation-venv/lib/python3.14/site-packages/numpy/…/tests/data/` 下——**是 Python 虚拟环境里第三方库自带的测试数据**（内容 `np.float32,0x80000000,0xff800000,3`）。因为 csv 在白名单里、而路径检查跑在其后，31 份库文件全部漏进工作堆。
**规则**：路径含 `site-packages` / `venv` / `.venv` / `node_modules` / `.git` / `dist` / `build` / `__pycache__` → **不看格式，直接判开发不晋升**。


**L1.5 格式白名单门（正向识别，不靠黑名单关键词打地鼠）**

公司正式交付物只有那几种格式，**用白名单正向放行，比堆黑名单关键词可靠得多**：

| 通道 | 格式 | 处理 |
|---|---|---|
| **工作文档** | docx/doc/pdf/ppt/pptx/xlsx/xls/**csv** | 进 L2 打分 → L4 AI |
| **图片** | png/jpg/jpeg/gif/bmp/webp/heic/tif | 走 OCR 通道（证照多在这里） |
| **CAD** | dxf/dwg | 走本地特殊预解析 |
| **非最终产物** | **md/json/txt/log/yaml/ini/conf/rtf** | **直接排除**——这些天生是中间产物、笔记、缓存、配置，不是最终文件 |

> CSV 属结构化表格数据，与 Excel 同级，**必须在工作白名单内**，不能和 md/json/txt 一起排除。

**实测效果**：940 份「待分拣」硬骨头 → 白名单一筛只剩 **135 份**真工作文档（xlsx 47 / pptx 31 / csv 17 / pdf 16 / docx 13 / xls 8 / doc 3），805 份 md/txt 直接排除，**降 86%**。

**⚠️ 白名单的一个漏网**：代码可以被存进 Office 壳。实测 `-.docx` 文件名只有一个连字符、扩展名合法，打开却是完整的 HTML+JavaScript 前端代码。故补 **L1.6 代码壳检测**：docx/xlsx 提取正文若命中 `<!DOCTYPE` / `function(` / `import ` / `tailwind.config` / `#include` → 判开发不晋升。

**L2 多信号加权打分（免费；工作为正、个人为负，算净分）**

| 信号 | 权重 | 说明 |
|---|---|---|
| 内容首行/摘要关键词 | ±4（最强） | 正文命中类目特征词 |
| 文件名关键词 | ±3 | 名字里的词 |
| 路径近处目录 | ±2 | 越靠近文件的目录越可信，远处减半；公司名/项目名目录是强信号 |
| 邻居投票 | ±2 | 同目录多数文件属哪类，补单个模糊件 |
| 扩展名 | 0（只路由） | 文档类只决定走文本提取还是 OCR，不定工作/个人 |

- 净分 **≥ +4 判工作，≤ −4 判个人，中间下沉 L3**。
- **路径不可靠的四招补救**：① 拆段看，近处目录权重高于远处；② 认出「中转站」目录（下载/桌面/微信接收/临时）时路径信号直接清零，只靠文件名+内容；③ 邻居投票；④ 看文件头认真实格式，不信扩展名（写着 .pdf 其实是图片的走 OCR）。
- **两条易错规则**：带个人名 ≠ 个人（职称申报/人员证件/劳动合同/体检报告对公司有用 → 工作）；迁移归档与素材图片属工作资产，不漏成待定。

**L3 加强嗅探（免费，只对 L2 模糊件；找硬证据而非再堆关键词）**
读开头 300–500 字，命中任意一条强证据当场定性、不进 AI：
- → 工作：公司全称 / 统一社会信用代码 / 「甲方乙方」「投标」「招标」「中标」「合同金额」/ 金额+币种+日期+盖章字样。
- → 个人：「身份证」「银行卡」「备考」「简历」且全文无公司名。

**L4 AI 概括（花钱，只收 L1–L3 都没判定的）**
读开头一段写一句话概括 + 复核类目。**人工彻底退出确认环节**——模糊件下沉 L4 让 AI 判，不靠人点头。

**L4 必做的两件事（不只是写摘要）**

1. **内容红线扫描（强制，上传前最后一道）**：正文命中 `apiKey` / `sk-` / `AccessKey` / `SecretKey` / `邀请码` / `invite code` / `password` / `token=` / 成批账号+邮箱清单 → **判敏感，禁上传**，单独出清单交管理员。
   > 为什么必须放在 L4：**格式门和文件名门都拦不住凭据。** 实测 135 份里揪出 6 份敏感件（阿里云百炼 apiKey 明文 csv、客户邀请链接 xlsx、员工邀请码 xlsx、平台邀请码 csv、客户组织账号清单 xls、客户方人员名单 xls）——它们全是 csv/xlsx 合法格式、文件名不含任何敏感词，**前置门一律判成「工作文档」放行，只有 AI 打开读内容才认出来。** 这是整条流水线最危险的一个洞。

   **红线要分三级，不能一刀切「禁上传」**（一刀切会误伤投标资质）：

   | 级别 | 判据 | 处理 |
   |---|---|---|
   | **S级 禁上传+高危清单** | ①**账号密码成对表**：表头同时含（账号\|账户\|用户名\|登录名\|邮箱）与（密码\|password\|pwd\|口令）；②`admin123` 这类默认口令；③平台 apiKey/AccessKey/SecretKey；④邀请码清单；⑤**身份证原件照片** | 禁上传，**单独出高危清单交管理员** |
   | **A级 脱敏后入库** | 职称证/社保证/毕业证/人员证件里含身份证号 | **允许上传，身份证号只留后4位**（这些是投标资格审查三件套，全拦等于扔掉最值钱的资质） |
   | **B级 限管理员域** | 客户方账号清单、人员名单（不含密码） | 上传但权限域收窄到管理员，不是禁上传 |

   **⚠️ 政府平台账号单独标红**：命中 `gov.cn` / `mohurd` / 人社厅 / 住建厅 / 职称评定 / 协会 域名且同表含账户密码 → 不只禁上传，**必须单独出高危清单**。这类泄露的后果是客户被冒名申报，比泄露 apiKey 严重。

   **实测最严重的两份**（文件名完全看不出）：
   - `经纬人员名单(1).xlsx` → 客户方全体员工「部门\|姓名\|账号\|密码」四列明文，密码=账号
   - `副本〈客户全称〉--各种项目注册信息.xlsx` → 客户官网后台 `admin/〈弱口令〉` + 住建厅报回款网站 + 省生态环保厅职称评定 + 高级工程师评定系统 + 中国资产评估协会账号密码（文件名完全看不出，正文是明文账密表）

2. **同名文件靠内容区分**：去重不能只比文件名或扩展名。实测 3 份同名 `材料表.xlsx` 分属不同工具输出、**型钢单位口径还不一样**（cm²/kg·m⁻¹ vs mm²/kg·m⁻¹）；2 份同名 `工作簿1.xlsx` 一份是绩效考核表、一份是 AI 漫剧分镜 Prompt 表。要比正文哈希或关键字段。

**L4 前置：老式格式必须先转换**
`.xls` / `.doc` / `.ppt` 用常规提取器读不出内容（实测 135 份里 8 份直接失败，占失败量的 44%）。**先转格式再提取**，否则这批文件会静默变成空摘要，被误判成无效文件剔除掉。

实测可用的转换路径（**本机没有 LibreOffice/soffice，别指望它**）：
| 格式 | 工具 | 备注 |
|---|---|---|
| `.xls` | **xlrd 2.x**（`xlrd.open_workbook`）| xlrd 2.0+ 只支持 .xls、已弃 .xlsx，正好对口。逐 sheet 逐单元格**取值**（`cell.value`），日期用 `xldate_as_datetime` 转 |
| `.doc` | `textutil -convert txt -stdout` | macOS 自带。**但会失败**，见下 |
| `.doc` textutil 失败时 | **Word piece-table 解析** | 见下方「textutil 报错不等于文件坏」 |
| `.xlsx`/`.docx` | openpyxl / textutil | — |

**装库注意**：macOS 系统 Python 受 **PEP 668** 保护，`pip install` 直接报 externally-managed。**建 venv 装**（`python3 -m venv`），别用 `--break-system-packages` 污染系统环境。

**⚠️ textutil 报错不等于文件坏 —— 必须走 Word piece-table 兜底**
实测 `山西金岩能源突发环境事件风评评估.doc`：textutil 报 `The file isn't in the correct format`，`file` 命令显示 `Name of Creating Application: Microsoft Visio`，看着像坏文件。**其实是有效 Word 文档 + 内嵌 Visio 对象**：
- OLE 流里有 `WordDocument`(1.9MB) + `0Table`，`wIdent=0xA5EC` 合法
- FIB 里 **`fComplex=1`** → 正文用**分段表(piece table)**存储，不是连续文本，所以 textutil 和"直接 UTF-16 解码"都读不出（后者只会得到乱码）
- 正解：从 FIB 偏移 `0x01A2` 读 `fcClx/lcbClx` → 在 `0Table` 里定位 `Pcdt`(标记 0x02) → 遍历 `PlcPcd`，每个 PCD 的 `fc` 最高位标记该段是 **8bit(cp1252) 还是 16bit(UTF-16LE)**，按 CP 区间拼接

**这一份救回 103,276 字**——是《山西金岩能源科技有限公司突发环境事件风险评估报告(备案本)》2025-10，藏在名叫「测试」的目录里。**若信 textutil 的报错当无效文件剔除，就丢掉了一份完整的环评风险报告。**

> **规则：textutil/常规提取器报错的 .doc，先查 OLE 流的 `wIdent` 和 `fComplex`，再决定是坏文件还是要走 piece-table。报错 ≠ 无效。**

**L4 提取失败的三种情况要分开标记，不能一律当垃圾**
| 情况 | 标记 | 后续 |
|---|---|---|
| 老式 xls/doc/ppt | `待转换` | 转格式后重提 |
| PDF/PPT 无文字层（扫描件、全图片 PPT） | `待OCR` | 走 OCR 通道 |
| 正文真为空（0 内容 docx） | `无效剔除` | 剔除 |


**自举校准（用原来的东西确认，不用人工挑种子）**
- **铁种子词典**：从已跑目录里挑**双信号自洽**条目（文件名命中类目 X **且** 摘要也命中 X，两个独立信号指向同一类，比人瞄一眼可靠）。本机挑出 641 份、15 类目。产物 `自举校准词典.json`。
- **扩展词典 v2**：铁种子覆盖窄（大量文档标题不含强词会漏判），故再用**原类目当弱标签**，统计每词在各类目的真实文档频率，扩到 20 类目 48 词。产物 `校准词典_v2.json`。
- **特征词频次直接当权重**（≥40→4，≥15→3，≥5→2，else→1），词典从数据里长出来，不拍脑袋。每轮 AI 结果再回填，越跑越准。

**工作堆内按类型路由控成本**：文档→AI 概括+归类；扫描证照→OCR（资质/验收类铁种子极少，正因多是扫描件，文字层读不到，本就该走 OCR 不走打分）；素材/媒体/归档→只登记不概括。

**实测（本机 7.1 万文件，扩展词典 v2）**：
- 全量 71,344 → L1 垃圾 683 + 开发 13,197；扩展名路由 素材/媒体/归档 53,603（只登记不进 AI）、文档 3,861。
- 文档 3,861 走漏斗：L2 判工作 1,223 / 个人 13；L3 硬证据拦 410（工作 396 + 个人 14）；**L4 进 AI 2,215**（原 ~3,790，**降 42%**）。
- 两口径：① 新漏斗独立判全量 → 进 AI 2,215；② 信任原类目明确的、只啃原「待分拣」995 份 → 新漏斗再捞 55，**真硬骨头 940 份必须 AI**（标题不含特征词，规则到顶，再扩词典会过拟合）。
- **误判纠回**（前置门纠「归属 + 粗类目」，细类目靠 L4 AI）：WorkBuddy 调研报告 会议纪要→项目报告；供热厂调研问卷 制度→项目报告；华豹白皮书 营销素材→产品资料；二外小升初备考 工作报告→个人；清网投标响应文件 个人→工作。

**L4 实跑验收（135 份硬骨头，逐份读内容）**：
- 归属分布：工作 96（含 16 份重复副本，净新增 80）/ 测试 demo 输出 14 / 个人 9 / **敏感禁上传 6** / 待OCR 6 / 无效 3 / 开发壳 1。
- 提取成功率 117/135 = 86%；失败 18 份 = 老式 xls·doc 8 + 无文字层 3 + 全图片 PPT 5 + 空文件 2。并发 8 线程约 40 秒。
- **AI 概括 vs 首行摘要的差距**：`工作簿1.xlsx` 首行无信息 → 实为 2016-2025 各部门绩效考核成绩表；`-.docx` 首行是 HTML 标签 → 实为交城供热智慧平台前端代码；`20250828154322_fbox_monitor_list.csv` 看着像日志 → 实为西门子 S7-200 smart PLC 点位采集表；`表1_各泄漏源最不利影响范围.csv` → 环评风险预测（逐源撤离线/疏散线距离 + 受影响村庄）。
- **外推警告**：940 硬骨头按 96/135=71% 算，真工作文档约 670 份，其余约 270 份是测试/个人/敏感/无效。**若跳过 L4 直接对 940 全量入库，会有 270 份垃圾和 6 类凭据混进知识库。**

**OCR 全量实跑验收（86 份证照候选）—— 四条硬教训**

**① 证照候选数别把中间产物算进去（我上一轮报的 287 是错的，真数 86）**
重新检查完整目录才看清，被误算进"证照候选"的其实是：
| 误算来源 | 真身 | 份数 |
|---|---|---|
| `t3-t6/pass*/page_XXX.png` | **PDF 逐页转图的 OCR 中间产物** | 898 |
| `述职报告/第X页.png` | 一份 PPT 被逐页导出成图 | 33 |
| `01-Downloads老文件` 的 UUID/canvas-image/whiteboard | 截图、白板导出 | 172 |
| `账号运营/_verify`、`artifacts` | 营销素材、封面参考图 | 85 |

> **规则：算"某类候选有多少"之前，先按目录语义排掉中间产物目录（`pass*`/`page_*`/`_verify`/`artifacts`/`extracted_images`/`第X页`）。否则外推倍数会虚高一个数量级——我据此说过"资质能翻 19 倍"，实际只有 +33 份。**

**② OCR 预处理的收益必须用关键词证据衡量，用字数衡量会得出完全错误的结论**
二轮做了图像预处理（灰度→放大 2-4x→中值去噪→autocontrast→Otsu 二值化），39 份问题件总字数 **2,582 → 13,809（+435%）**，0 字失败从 11 份降到 0。看着像大胜。

**但按关键词证据选优后，86 份里只有 10 份二轮真的更好，76 份一轮就够。** 暴涨的字数大部分是**幻觉字符**：`image216.jpeg` 从 0 字变 2925 字，内容全是 `. | KA . (oe orn we SR SN` 这种噪声——那是张**纯照片**，被 4x 放大 + 二值化后 tesseract 从图像纹理里"读"出了根本不存在的字。

> **质量分公式（不看字数）**：`证照关键词命中×权重(2~3) + 真实中文双字词命中×0.5 − 噪声惩罚`；噪声比 = ASCII标点数/(中文数+标点数)，**>55% 扣 8 分**；中文 <20 字扣 3 分。
> **两轮都跑，取质量分高的那轮**，不取字数高的那轮。
> 靠这条，29 份纯照片被正确判为「无效-无文字层」，而不是被误当成有内容的证照入库。

**③ 身份证号必须过 GB11643 校验位，否则 18 位证书编号会被误判成身份证号**
实测 `image257.png`（毕业证）的**证书编号 `112421202205500459`** 是 18 位纯数字，被我的正则当成身份证号，还做了"脱敏"输出 `112421********0459`——**把证书编号毁了，同时误报了一起身份证泄露**。

> **校验规则**：18 位 → 地区码 6 位 + 生日 8 位（`1900≤年≤2015`、`1≤月≤12`、`1≤日≤31`）+ 顺序 3 位 + 校验位；校验位按 GB11643 加权模 11 对照 `10X98765432`。**不过校验的一律当证书编号，不当身份证号。**
> 附带结论：本机 8 份真身份证**0 份过校验位**——不是判错，是低分辨率 OCR 读不全 18 位。靠「居民身份证/公民身份号码/签发机关/有效期限」关键词判 S级即可。**读不全反而降低了泄露面，但仍必须拦。**

**④ 字段抽取要加"不像人名/不像主体"的黑名单**
实测误抽：`姓名='参加太原'`（原文"参加太原市…培训"）、`姓名='具有相应'`、`主体='月在本学院'`（原文"…月在本学院学习"）。
> **规则**：姓名首字必须在百家姓集合内 **且** 不含禁用词（参加/具有/相应/该同志/公司/学校/专业/证书/评审/培训…）；主体必须匹配完整机构后缀（有限公司/设计院/研究院/大学/学院/促进会），且排除 `月在本`/`在本`/`学院$` 这类残句。

**OCR 实跑账面**：86 份 → 可入库 33（A级脱敏 25 + 工作 7 + 限管理员域 3，其中 2 份零质量已移待复核）/ **S级禁上传 8（身份证）** / 纯图片无文字 29 / 待复核 14。
**淘出的真金**（典型结构，数量按各机不同）：职称证（〈客户全称〉·高级工程师·〈专业〉）、毕业证（〈院校〉·〈专业〉）、社保参保记录（起止年月）、培训合格证（含证书编号）、营业执照、发票。
> **职称证 + 毕业证 + 社保是投标资格审查三件套，缺一份就废标。** 它们常躺在 `图片/证件/imageNNN.png` 里，文件名零信息，**不 OCR 就等于公司没有这些资质**。


### 4.1 目录文件检索与内容分类

1. 默认列出本机盘位与大目录（盘符/挂载点+容量），员工选全读或指定文件夹/盘位；白名单根目录，系统目录与个人目录默认排除。
2. 目录文件检索 + 基础解析；**真实格式识别**（不信扩展名，纠正错扩展名）；扫描件 OCR。
3. **按内容两段分类**：先规则（路径/扩展名/关键词/类目描述），再 LLM 读内容对照文件计划分类；必须附原文证据 + 置信度；低于阈值进人工队列，不许猜。
4. 去重：内容哈希 + 语义相似；同哈希保留最新、记录全部来源人。
5. 产出工作目录 CSV：原文件名/路径/哈希/真实格式/建议JD编号/建议新名/主体/owner建议/有效期/置信度/证据/标记（个人/过期/敏感/重复）。
6. 附本机命名规则说明 + 整合建议；生成**虚拟目录计划**（只提议、不动文件），员工预览确认。
7. 目录上传知识库 + 输出【目录上行】消息；本步不移动任何文件。

### 4.2 表格与图两类特殊文件的处理铁律

**1. 表格（xlsx/xls/csv）存储态永远是原件，禁止转 md**

- 客户要原件，xlsx 的公式/合并单元格/多 sheet 一转 md 全丢，等于毁档案。
- md 只作为「喂大模型那一下」的临时形态；抽主体、建台账用 openpyxl/xlrd 直接读，不转 md。

**2. 图（图片/CAD/图纸/老扫描件）走「描述 + 备注」两字段**

| 字段 | 谁填 | 内容 |
|---|---|---|
| `content_desc`（图文描述） | VLM 批量，客户端跑 | **客观**描述画面/图纸里有什么 |
| `human_note`（人工备注） | 人，走「待认领/待核对」待办 | **主观**归属：XX 项目的 XX 图/铭牌 |

> **判据**：OCR 出字 ≠ 出主体。字数高但抽不到主体 → 是版面问题（A3 图纸的"设计单位"在图框角落），走 VLM；字数低 → 是清晰度问题，先升 DPI 重试。
> VLM 给客观「描述」，补不了主体；人给「备注」才能补主体。纯设备照/现场图里没有主体，VLM 变不出公司名，只能靠人备注——别指望大模型。

## 7. E-校对与改名/上传（人员决定，可延后）

**v0.3 关键变化**：改名和上传都不再是强制步骤，由人员决定。先导出「改名映射」和「目录文件名」，个人想改再改、想传再传。

1. 对照总目录逐条校对；对话确认异议（个人/过期/分类），异议上行；确认后锁定。
2. **改名（可选，个人决定）**：先导出「改名映射」（原名 → `类别_主体_名称_日期` 新名，JSON），个人决定改不改。**不改也行**——全公司目录已用新名索引了这个文件，随时能改，改名映射先存本机。拆分（一文件多证/表格与正文/多项目）同样作为建议，不强制执行。

**命名五条硬约束（本机 965 份实测后定稿，产物《命名规则书.md》= JD `00.01 规则与命名`）**

```
类别_主体_名称_日期.扩展名        ← 固定 4 段，程序按 _ 切分永远得到 4 段
```

| # | 约束 | 不守会怎样（实测真发生过） |
|---|---|---|
| 1 | **段内禁止下划线**，原名的 `_` 一律换 `-` | `煤矿污水处理运维标书_服务承诺` 让名字变成 5 段；`00-项目主档_V1.0_20260818` 变 7-8 段，**406/965 份段数失控** |
| 2 | **状态标记不进文件名**，写清单独立列 | `【重复】发票_...`、`【待OCR】培训_...` 共 27 份以方括号开头。状态会变，名字不该跟着变 |
| 3 | **扩展名只在最末出现一次** | `微信图片-181412-214-日期待核.jpg_2025-08.jpg` —— 名称段里残留了 `.jpg`，**472 份中招** |
| 4 | **一个抽屉只能有一个类别词** | `20.03` 抽屉里同时出现 `投标文件与报备台账`(6) / `投标台账`(3) / `【重复】投标`(3)；`50.01` 里 `客户宣讲与提案PPT`(152) 和 `宣讲提案`(5) 并存。**根因：前缀剥离正则限定了 2-8 字，9-10 字的长前缀没被匹配到** |
| 5 | **总长 ≤100 字符**，超长先砍名称段 | 不砍类别和主体，否则破坏可解析性 |

**类别词表是封闭集合**（示例 34 条），新增要走总管理签核。**主体必须用全称**，简称走别名表补全（如 `某某`→`某某（山西）设计院有限公司`），否则检索时同一主体分裂成多个。

**日期三级回退**：文件名年份 > 父目录年份 > 正文抽取。正文日期与路径年份相差 3 年以上判为抽取错误。**完全无线索填 `日期待补`，绝不填今天的日期**（会造成"文件是新的"假象）。

> **主体填不出来是常态，不是失败**：本机 965 份里 630 份（65%）主体待补。三个来源全试过——内容摘要只能补 23 份（3%，因为摘要只是首行标题不是全文）、原文件名 14 份、路径段映射约 120 份（`01-Downloads老文件`184份、`环保行业`77份、`测试`91份这类目录零信息）。**要补全只有 AI 读全文（约 ¥3-5）或人工补两条路。规则是：填不出就写 `主体待补`，不许瞎猜。**
> **人工补的优先级**：`10.04 人员证件` 和 `20.01 合同` 先补——这两类主体错 = 资质挂错公司 = 投标废标。

**定稿阶段必查的 4 个质量问题（本机 965 份实测，每个都真发生了）**

| # | 问题 | 实测例子 | 修法 | 命中 |
|---|---|---|---|---|
| 1 | **类别前缀不统一** | 同一抽屉里混着 `人员_` 和 `人员证件_`（因为一部分名字来自 AI 建议、一部分是程序按抽屉名生成的） | 建**抽屉→前缀映射表**（34 条），全部按表重写前缀 | **439 份** |
| 2 | **抽屉被污染** | `10.04 人员证件` 里混进了「标书检查问题清单」「ai工程师企业宣讲视频」「创青春大赛申报书」「天镇县AI智慧农业厂商选型对比」 | 对**易污染抽屉**（人员证件/公司资质）按摘要+文件名强特征重判：`标书检查→交付方法论`、`宣讲视频→视频脚本`、`大赛申报书→投标台账`、`选型对比/合作方案→客户方案`、`装订送审说明→通用模板` | **9 份** |
| 3 | **零证据件混进正式抽屉** | OCR 质量分 0（无任何证照关键词命中）的 `营业执照.jpg`、`微信图片_2025-08-19.jpg` 被判"工作"进了 `10.01 公司资质` | **质量分 0 → 强制移 `00.03 待复核`**，不许进正式抽屉 | **2 份** |
| 4 | **日期错** | `11.2025年度山西省专业技术人员考核登记表` 的日期列是 `2003-04`（正文里抽到的无关日期） | **三级回退**：文件名年份 > 父目录年份 > 正文抽取；冲突时以文件名为准，并在冲突标记里留痕 | **32 份** |

> **规则：定稿不是把各轮结果拼起来就完事。** 多轮跑（规则轮 / AI 轮 / OCR 轮 / 转换轮）产出的名字和日期口径不一致，拼接后必然出现前缀混乱、抽屉污染、日期打架。**定稿必须再过一遍这 4 项检查**，否则清单交出去客户一眼就看出"这名字不对"。

> **易污染抽屉要主动查**：`人员证件`、`公司资质` 这两个抽屉最容易被塞进不像证件的东西——因为它们是按"路径在证书目录里"归的，而路径不可靠。**对这两个抽屉做一次"名字里有没有证件特征词"的反向校验。**

3. **上传（可选，接知识库技能）**：要上传时，走知识库技能接口——**每人带自己的 API key**（权限域随账号绑定），文件上传到**预先定好的固定目录路径**，上传后异步解析切块向量化；**不上传就先不动**，改名映射与目录结构存在本机。复制不移动，原件保留。
4. 特殊格式（CAD/特殊 PDF）本地预解析，解析件 + 源文件同传挂源索引关联。
5. 写**回滚日志**（每次移动/改名的逆操作）；输出【上传完成】+ 上传清单（哈希→JD→新名→目录→域）。

## 13. 完整流水线（七步，开箱可跑）

这一节是**操作手册**。每一步都有脚本、固定产物、固定判据；能跑哪步取决于权限和是否配了大模型 Key，跑不了就停在那步并说明，不跳步、不猜。

### 13.0 一次跑完（顺序固定）

```bash
OUT=./kb-整理
python3 scripts/scan_l1.py    --root "$HOME" --out "$OUT"                  # 1 第一层
python3 scripts/make_report.py --out "$OUT" --root "$HOME" --name "姓名" --dept "部门"  # 2 报告
python3 scripts/classify_l2.py --out "$OUT" --root "$HOME" --name "姓名" --dept "部门"  # 3 分类
python3 scripts/fill_gaps.py   --out "$OUT"                                # 4 批量补
python3 scripts/parse_all.py   --out "$OUT" --root "$HOME"                 # 5 全量解析
python3 scripts/ai_fill.py     --out "$OUT"                                # 6 AI 补齐（需 Key）
python3 scripts/merge_ai.py    --out "$OUT"                                # 6.5 合并 AI 结果 → L3
python3 scripts/finalize.py    --out "$OUT" --root "$HOME"                 # 7 定目录+改名映射
```

**第 7 步默认 dry-run，只出映射，不动任何文件。** 用户明确说“执行改名/复制”时，才加 `--apply --dest <目标目录>`；且只复制、不移动、不删除。

### 13.1 每步做什么、产出什么、什么情况停

| 步 | 脚本 | 做什么 | 产物 | 停的条件 |
|---|---|---|---|---|
| 1 | `scan_l1.py` | 只登记 + 前置分拣：垃圾/依赖/中间产物排除，白名单格式放行 | `01-全量文件清单.csv`、`02-工作文档候选.csv`、`03-图片与CAD候选.csv` | 无（只读清点） |
| 2 | `make_report.py` | 生成人读的第一层报告 + 文档哈希/重名 | `第一层-磁盘检查报告.md`、`08-工作文档-哈希与重名.csv` | 无 |
| 3 | `classify_l2.py` | 逐份读内容，规则+语义打分定抽屉、抽主体/日期 | `09-分类结果.csv`、`10-目录结构建议.md`、`个人索引包-L2.json` | 不调外部服务，不会停 |
| 4 | `fill_gaps.py` | 批量消待补：模板豁免、项目名、目录继承、通用件、日期回退 | `11-待补项-按目录批量补.csv`、`12-待补项处理说明.md` | 无 |
| 5 | `parse_all.py` | **全文解析**：docx/pdf/pptx/xlsx/csv/doc/xls/dxf 全文落地 | `13-全文解析缓存.jsonl` | 无（扫描件标 `待OCR`） |
| 6 | `ai_fill.py` | 大模型读**全文**（长文分段），定抽屉、补主体/日期、给证据 | `14-AI补齐缓存.json` | **没有 `SPACEAGENTS_AUTO_API_KEY` 就停**，说明只到规则层 |
| 6.5 | `merge_ai.py` | 把 AI 结果并回索引：主体/日期/抽屉只补不猜 | `个人索引包-L3.json` | 无 |
| 7 | `finalize.py` | 按命名规则校验、定目录、出改名映射 | `15-最终目录树.md`、`16-改名映射.csv/json`、`17-终稿索引包.json` | 名称校验不过的进 `hold`，不自动改 |

### 13.2 命名规则校验（第 7 步内置）

`类别_主体_名称_日期.扩展名`，四项硬校验，不过就是 `hold`：

1. 按 `_` 切分必须 4 段
2. 段内不得再有下划线
3. 名称段不得残留扩展名（`.docx`/`.jpg` 等）
4. 总长 ≤ 100 字符；不得含 `【】`

日期三级回退：文件名 > 父目录 > 正文 > 文件修改时间（只取年份，标「日期待核」）。**绝不填今天。**

### 13.3 AI 补齐的边界（第 6 步）

- 把**每份文件的全文**发给模型（不传附件、不传图片）。单份超过 24000 字时按段切分（重叠 800 字），逐段抄机构名/项目名/日期/抽屉倾向，再本地聚合：项目名优先、机构名按出现次数、日期取最明确的一处。
- 模型只允许：选一个 JD 编号、抄一个原文出现的机构名/项目名、抄一个明确日期。
- 找不到就留空；**禁止拼接、改写、推测**。
- 模型返回的 `evidence` 必须能在原文里找到；找不到的那条作废，回退第 4 步结果。
- 中间产物、系统导出日志、工具验证样例、空表模板**不送模型**，直接标 `00.03/skipped`，省时间也避免把日志当业务文件。
- 结果按文件缓存（`14-AI补齐缓存.json`），重跑不重复计费。

### 13.4 图片通道（单独一批，不混进文档流水线）

图片不在七步里自动跑，因为量大。做法：

1. 先用 `07-图片-疑似中间产物.csv` 排掉 `pass*/page_*/_verify/artifacts`；
2. 剩下的按目录语义分「证照候选 / 素材素材 / 截图」；
3. 只对证照候选跑 OCR，**按关键词证据算质量分，不按字数**；
4. 身份证号必须过 GB11643 校验位，不过的一律当证书编号。

### 13.5 安全底线

- 全流程只读原件；第 7 步 `--apply` 也只复制。
- S 级敏感件（账号密码同表 / 密钥明文 / 邀请码 / 身份证原件）标 `禁上传`，只出清单交管理员。
- 不做自动发布、不自动上传；上传必须用户点头并走知识库接口。


## 14. 第二层：上报包与部门融合

### 14.1 三层结构

| 层 | 谁 | 拿到什么 | 产出 |
|---|---|---|---|
| 第一层 个人 | 员工（E） | 自己电脑 | 终稿目录树 + 改名映射 + **上报包** |
| 第二层 部门 | 部门经理（M） | N 份上报包 | 部门融合包 + 签核单 |
| 第三层 公司 | 总经理（G） | N 份部门包 | 全公司目录 + 权限域 |

**部门不另建一套文件夹树**：部门 = 若干类目的 owner + 一个权限域。融合是「去重 + 定类目 + 定权限」，不是把大家的目录拼起来。

### 14.1.1 文件名强规则（finalize 内置，先于 AI 判定）

文件名本身足够明确时，不采信 AI 的抽屉判断，直接覆盖并记 `规则覆盖:<理由>`：

| 命中文件名 | 归入 | 说明 |
|---|---|---|
| `t/tmp/temp/test/preview/预览*` | 不入库 | 测试、渲染预览 |
| `pytest/样例/sample/demo` | 不入库 | 工具验证样例 |
| `在职/离职/收入/工作证明` | 30.01 人员证件 | |
| `审核/审查/评审/修改意见`、`闭环清单` | 80.01 项目档案 | |
| `GB xxxxx` | 50.01 产品资料 | 标准规范 |
| `统计`、`地类`（非「图」） | 80.01 项目档案 | 项目统计数据 |
| `flange/hex_bolt/bolt/gear/T*_` | 50.04 图纸CAD | 零件图 |

命中后按 `类别_主体_名称_日期` 重建名字（原名里的 `_` 转 `-`，去 `#`/`【】`），因此不会触发命名校验失败。

### 14.2 第一层产出：上报包

```bash

  --name "张三" --dept "交付部" --role 员工 --to "李经理"
```

产物：`上报包-张三-20261118.zip`

**包里只有元数据**：不含正文、不含本机绝对路径、不含敏感件（只报数量）。所以可以直接发。

### 14.3 怎么发给第二层（按可用通道，从低到高）

1. **人工转发（现在就能用）**：把 zip 丢到飞书/微信，附上那段标准消息。对方拖进他的 SA 对话。
2. **共享目录**：部门共享盘放一个 `上报/` 目录，每人把 zip 放进去，经理指向这个目录。
3. **接口（SA-01 接通后）**：消息文本不变，改成接口收发，zip 走附件。

**判定「发给谁」**：`--to` 填直属经理；不填就是本部门经理。跨部门借调的人，按 `--dept` 走，不按汇报线走。

### 14.4 第二层怎么融合

```bash
python3 scripts/merge_dept.py --out ./部门融合 --packages-dir ./收到的上报包 \
  --dept "交付部" --manager "李经理"
```

产物：

| 文件 | 内容 |
|---|---|
| `20-部门融合包.json` | 合并后的部门索引（带来源人、权限域） |
| `21-部门目录树.md` | 部门目录 + 权限域建议 |
| `22-冲突清单.csv` | 全部冲突 |
| `23-签核单.md` | **只列必须签核的**，其余按人汇总 |

**自动判定规则（不需要人逐条看）**：

| 情况 | 判定 | 处理 |
|---|---|---|
| 同一份文件多人都有（同哈希） | 重复 | 合并为一条，记来源人 |
| 同哈希但抽屉不同 | 类目争议 | 取票数多的，记冲突待确认 |
| 同目录同名、哈希不同 | 版本冲突 | 保留日期最新，另一份标「旧版」 |
| 置信 <0.7 / 主体待补 / 继承待核 / 日期待核 | 待复核 | 汇总到原上报人，不进经理签核单 |

**冲突分两级**：`blocking`（版本冲突、类目争议）必须经理签核；`review`（待复核）按人汇总，谁的文件谁回去补。这样经理通常只需看 5~15 条。

## 15. 依赖体检与一键流程（v1.4）

### 15.1 先体检，再动手

```bash
python3 scripts/doctor.py                 # 本机缺什么
python3 scripts/doctor.py --deps "<盘位>/kb-deps"   # 已装到自定义目录时
```

检查三类：解析库（python-docx / openpyxl / xlrd / python-pptx / pymupdf / olefile）、外部工具（textutil / antiword / catdoc / soffice、tesseract）、可用盘位与剩余空间。

**老格式不等于必须装 LibreOffice**：

| 格式 | 做法 | 说明 |
|---|---|---|
| `.xls` | `xlrd` 直读 | 结构化解析，准确，不用转换 |
| `.doc` / `.ppt` | `olefile` 抽 OLE 流里的原文 → 交大模型判断 | **不装 LibreOffice / antiword**；抽不到就标 `legacy_unreadable` 列清单 |

为什么不用转换工具：本地转换会丢表格与版式，转出来的文本和原文对不上，分类和命名反而偏。抽取原文 + 模型判断，比"转成纯文本再猜"更接近事实。模型只写能从片段确认的字段，不确定留空。

`doctor.py` 会输出 `doc_reader` / `ppt_reader` 实际用了哪个，以及 `notes`（按平台给最小依赖建议）。

输出 `missing`（缺哪些 pip 包）、`need_old_format_converter`（.doc/.xls/.ppt 需 LibreOffice）、`volumes`（可选盘位）。

### 15.2 装依赖：必须由用户指定盘位

```bash
python3 scripts/install_deps.py --target "<盘位>/kb-deps"          # 只装缺失的常用包
python3 scripts/install_deps.py --target "<盘位>/kb-deps" --all     # 全部解析库
```

规矩：
- **不许**装到系统盘、系统 Python、`site-packages`
- 安装前检查剩余空间（<200 MB 直接拒绝）
- 装完用 `--deps` 或环境变量 `KB_STEWARD_DEPS` 交给后续脚本
- 网络失败时提示换镜像源，不静默重试

### 15.3 一键跑完

```bash
python3 scripts/run_all.py --out ./kb-整理 --name "<姓名>" --dept "<部门>" --role "<职位>" \
  --scope "<路径1>" --scope "<路径2>" --deps "<盘位>/kb-deps"
```

顺序：体检 → 检查目录 → 报告 → 分类 → 补待补 → 全文解析 → AI 补齐 → 合并 → 定目录 → 人读索引。
缺依赖默认停在体检这一步；`--allow-missing-deps` 可先跑，缺库文件标 `missing_dep:<模块>`。

范围选择：`run_all.py --list-roots` 列出盘位与常用目录（含剩余空间与顶层文件数），由用户勾选。

### 15.4 三类产物（不要混）

| 产物 | 读者 | 内容 | 禁止出现 |
|---|---|---|---|
| `目录索引.md` | 人 | 抽屉分组 + 一行一份 + 一句话内容 | 哈希、置信度、字段名 |
| `改名对照.md` | 人 | 原名 → 新名 两列 | 同上 |
| `17-终稿索引包.json` | 智能体/第二层 | 完整字段（抽屉/主体/日期/哈希/权限域） | — |

人读文件由 `make_human_index.py` 生成，摘要取自 `13-全文解析缓存.jsonl` 的正文首句，不额外调模型。

### 15.5 文件名带原文件名括注

`finalize.py` 默认开启 `--keep-orig`：新名为 `类别_主体_名称_日期（原：原文件名）.ext`。
- 括注部分不参与「4 段」校验
- 总长上限放宽到 150 字符，超长先截原名
- 用户不要时加 `--no-keep-orig`
